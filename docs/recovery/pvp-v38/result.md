# v38：星币与本地训练候选版

用户反馈 v37 没有可出战僵尸且只有 1 星币；旧星币充值无效。本轮以“购买星币 → 支付星币训练 → 等待完成 → 保留可出战僵尸”作为优先测试范围。

- 原星币三档数量保留，购买方式改为钻石：110 → 5000，440 → 20000，1650 → 75000；不叠加手续费或充值赠送，显示“获得X星币”。
- 接管星币购买的成功回调与通用发放入口，仅处理 pvpCoin；其他商品沿原路径。原生支付流程负责钻石余额检查和扣费，本地写入失败则返还该笔钻石。
- 星币是 PvPManager+4（ag），不是基地等级。v31 误将该字段当作等级，初始化为至少 1；v38 在旧大厅初始化后恢复本地账本余额，避免花完后又多出 1 星币。
- 训练类型来自原版 TRAININGTYPES。最低级僵尸为 pvp_change，成本 5 星币、占 1 空间、训练 30 秒；v37 的 tutorial_armor1 不是训练队列认可的类型。去除那条无效的免费初始军队，按购买和训练流程获得僵尸。
- 按原版类型的费用/时长/解锁等级处理入队，提供取消返还、等待完成、重启恢复和余额/容量拦截。当前本地基地按至少 1 级初始化，容量 40、并行类型 6；升级、研究、其他商铺消费和战斗消耗/结算尚未实现完整本地闭环，不能宣称整套 PVP 经济已完成。
- 星币与训练队列保存在应用自己的 files/userdata/offline-pvp-<profile>.eco，带玩家标识、版本、长度和校验和，以临时文件+同步+重命名保存。损坏文件阻止交易，不覆盖。该文件在用户规定的备份/回档范围内。
- 保留 v36 已验收修复及 v37 邻居/布阵候选逻辑。初期教程阶段不接管本地训练；邪恶戴夫与攻防流程仍待实测。

原生实现包含独立可写运行缓存段，保留原有加载/展开头并移动程序头表，代码段仍为只读可执行。字符串扩展接在已有本地化处理之后，并修正了新增入口的 ARM 对齐。

构建：python scripts/build_pvp_v38.py；--native-only 只构建原生部分。
检查：python scripts/check_offline_economy_arm.py 在非零基址运行 APK 内的 ARM 代码，覆盖购买失败不发放、余额与训练重启、取消返还、容量拦截、保存失败返还钻石、损坏账本拒绝交易、玩家隔离、教程隔离和新旧本地化衔接。外部支付/界面/原生类型校验以边界替身表示，仍必须由用户实测。
