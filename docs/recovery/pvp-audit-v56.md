# 中文版 1.7.5 离线 PVP 功能审计

日期：2026-11-04。基线：main 74ce986、已验收 v56。

本次为网络资料、原包配置、离线实现及历史验收记录对照，没有启动游戏。下文“已验收”仅覆盖记录明确确认的操作，不代表全部种类、等级和异常路径通过。没有改动 APK 或玩家存档。

## 用户决定的恢复范围

用户明确要求删除联赛与排行榜功能，不再恢复其入口、排名及联赛周期奖励。保留其余恢复目标；奖杯是否用于其他原版进度条件应独立核对，不能连带删除区域解锁或任务需求。每次只推进一项可验收改动，通过后再推进下一项。药剂范围为第一步，删除联赛/排行榜为后续独立步骤。

## 对照范围与资料可信度

目标是旧版“对战 / 花园战争”，不包括新版“双人对决”、国际版 Arena 或超 Z 联赛。

- [2016 年失落之城版本报道](https://mobile.qudong.com/article/243455.html)：同时期资料，确认花园战斗、资源争夺、占地生产、联赛榜单、军队与实验室这些模块。
- [Battle Wiki](https://plantsvszombies.fandom.com/wiki/Battle)：搜索索引可读，正文抓取受限；用于辨认旧模式、戴夫六轮挑战及版本变动，不把其中跨版本数值直接当成 1.7.5 配置。
- [中文百科“花园对战”](https://www.newton.com.tw/wiki/花園對戰/62909806)：辅助核对资源地盘、四种技能、货币用途。
- [2020 年玩家攻略](https://www.taptap.cn/moment/15209681244915538)：确认兑换商店、战斗记录/复仇、训练场和实验室的玩法关系；后期商品、植物、价格和活动周期不直接纳入 1.7.5 恢复标准。

数值冲突优先查原包。例如网上介绍五分钟，本地 ARENA_BATTLE_TEST 配置为 360 秒；Wiki 的历史钻石奖励也有版本变化，不能照搬。资料提到的每日补给、戴夫周期、联赛奖励具体数值仍需原版配置或同期录像确认。

## 本地证据

### 补充：药剂范围（用户新反馈）

用户确认四种药剂目前作用范围均为 1×1，需优先修正。用户提供的 Wiki 表格给出以下目标：瘟疫药剂 3×3、僵尸血包 4×4、战争迷雾 3×3、狂暴药水 5×4。此目标作为用户要求记录；尚未完成代码修改或运行验收。

抽出的原包属性中，四种技能均为 `SkillScope: 0`；瘟疫药剂 `SkillRadius: 0.5`，其他三种 `SkillRadius: 1`。不能把半径字段直接当作方形格数，必须继续定位范围枚举、坐标单位、范围检测及指示器的解释方法，避免只扩大贴图而实际仍只影响一格。

[Wiki 的版本说明](https://plantsvszombies.fandom.com/wiki/Battle)另记载 1.9.0 扩大过技能范围，因此表格未必对应 1.7.5。本次遵照用户要求列入扩大范围目标，不以旧版本差异否决修复；价格、持续时间和研究数值不随此项擅自变更。

验收需分别检查：中心与边缘目标是否受影响、范围外目标不受影响、拖动指示与实际作用一致、草坪边缘裁切、多只僵尸同时生效、不同技能等级、坐标缩放，以及阵亡/离开范围后的效果清理。偶数宽高应先明确覆盖格选择规则，不能仅凭截图估算。

- `src/offline-pvp/economy.h` 的 Economy 记录含钱包、训练、三种建筑等级/升级计时、产出和 daveWins；没有研究、地块归属、奖杯、战斗历史、商店库存等记录。此结论结合接管入口检查，并非仅凭字段缺失推断。
- `src/offline-pvp/progression.h` 明确只处理 kind 1..3 建筑升级，并注明研究页独立；`produce` 处理基地两种货币的按时产出。
- `src/offline-pvp/offline.cpp` 的 `offlineBattleResult` / `persistBattleArmy` 保存死亡损耗和一次戴夫胜利；`offlineResultContinue` 保留本地余额以免被空服务器结果覆盖，没有战利品计算。
- `src/offline-pvp/neighbors.json` 定义六个普通邻居与一个戴夫，戴夫使用 `offline_evil_dave_v1`，不是已还原的服务器原阵容。
- `work/pvp-v38/PVPSHOPCONFIGDATA.RTON.json` 原商城存在固定/随机商品和刷新配置（64800 秒）。这与后期攻略的商品轮换周期不是同一个概念。
- `work/pvp-v54/PVPUPGRADE.RTON.json` 保留建筑升级数据；`work/pvp-v55/research-presets.json` 保留研究属性；这些原始资料可用于后续恢复，不代表已经接通功能。
- 实际验收范围见 [进度总表](README.md) 及 v42、v49、v51、v52、v53、v55、v56 的结果记录。

## 建议恢复顺序与验收目标

0. **分步执行**：药剂范围验收 → 删除联赛/排行榜并验收 → 下述各系统分别实现、分别验收。未验收的改动不打包成多项同时测试。

   **药剂实际范围与指示器**：优先定位上述 1×1 缺陷，按用户指定目标修复真实判定及显示；此前“技能正常”不再涵盖范围正确性。
1. **战斗经济闭环**：费用、胜负奖励及幂等保存；奖杯的非排名用途另行核对；重复点继续、重启不能重复领奖或丢钱。先固定版本数值，不能直接照搬网页的旧价。
2. **僵尸与技能研究**：原配置驱动的解锁、等级、费用、计时、钻石完成、战斗属性与冷启动保留；逐种逐级测试。
3. **戴夫六轮挑战**：六套独立阵容、胜场推进、胜负台词、奖励及重开规则；原服务器阵容继续考据，找不到时明确标为本地替代。
4. **兑换商店**：让奖章有实际消费用途，验证物品入包、库存刷新及跨重启；失败不扣费、重复请求不重复发货。
5. **资源争夺**：地块归属→占领→驻防→生产→收租→被攻占，随后接 NPC 反击及地区扩张。
6. **记录与复仇**：本地攻防日志、复仇与防重复领取；回放需单独确认证据与范围。联赛、排行榜及其专属周期奖励按要求删除，不恢复。
7. **完整回归**：首次新玩家引导、12 种训练数据对应军队与四技能、混合军队、满队列/容量、余额不足、升级到顶、跨离线产出、失败/超时/全灭/主动退出、场景连续切换、重启和多玩家隔离。

所有后续运行仍先备份、由用户测试、完成后回档并逐文件校验。首次发放测试应使用正常创建的测试玩家；不得修改玩家存档强推引导。使用哪位玩家须遵守用户指定的 WSA USER 规则或先取得新的明确指示。

## 保留的用户定制

金币/钻石互换及手续费规则、星币钻石购买、训练钻石加速、admin 兑换码、鼠标键盘操作、存活僵尸回收，以及已删除的商业弹窗均按用户要求保留。它们与旧服务器版本的差异不作为“恢复失败”，也不能为了对齐攻略擅自撤销。
