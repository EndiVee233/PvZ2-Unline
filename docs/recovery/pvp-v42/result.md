# v42：接入独立 PVP 星币窗口

v41 的通用商店点击处理未覆盖用户打开的独立 PVPCoinBank，用户购买仍无扣费/到账。已读取日志、关闭游戏并回档，32 个文件逐一校验。PVP 钻石显示的用户结果尚未单独反馈。

从 PVP 货币栏购买按钮追踪至 `0x40b154`，发现它构造 `0x10711b0`，与普通钻石/金币银行完全不同。该窗口持有 `pvpCoins` 商品分类的弱引用，实际按钮方法是 `0x1070990`：按索引取得分类中的商品，检查钻石够不够，关闭本窗口，然后调用 `0x104309c(manager,index)`。原方法只将索引发给旧服务器，本身没有扣除钻石。

v42 接管该独立购买请求，在常规离线 PVP 阶段按原分类中稳定的三档顺序（5000、20000、75000）和用户确定的价格（110、440、1650）执行现有本地交易：原生钻石扣费，星币本地持久化和原生余额通知，写入失败退款。构建检查确认 pvpCoins 分类的三档顺序未被资源更新改变，非法索引拒绝交易；早期教程保留原流程。通用商店兼容入口、PVP 钻石栏和已验收 admin 等其他功能保留。

ARM 检查直接执行独立窗口的原始 `0x1070990` 按钮代码，覆盖其真实分类/商品查询、原钻石额度判断、关闭窗口以及实际调用 `0x104309c` 后进入本地交易；三档分别验证精确扣费与到账。引擎边界替身仅用于资源引用、货币方法和 UI，并不替换原始按钮分支。另测本地请求余额不足、写入失败退款，以及既有兑换码、训练和 ELF 布局检查。游戏实际交易和训练持久化仍待用户验收。

构建：`python scripts/build_pvp_v42.py`。资源包及启动 DEX 与 v41 相同。PVP 完整战斗、升级、研究、结算及邪恶戴夫全流程仍未完成验收。私有存档和日志不提交。
