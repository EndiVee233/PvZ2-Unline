# v95 多样邻居与特殊对手（候选，待运行验收）

本轮按用户要求先恢复邻居生成和“更换对手”，NPC自动反击、防守结算、回放、复仇留到下一轮。商铺阵容不变；戴夫使用独立的既有六轮流程。药剂和海鸥视觉待办不标记完成。

## 普通邻居

从原包 `GamePropertySheet.PlantTypeOrder` 的110种可获取植物出发，结合原生类型枚举、PropertySheets费用/最高阶数建立95种陆地防守候选。资源RTID不等于原生植物枚举，生成器从原生类型构造函数提取映射，特别核对强酸柠檬71、冰西瓜34、火龙果316。排除立即消失、必须有目标或水域的15种植物；冰冻生菜保留。完整名单和排除原因由构建生成的 `neighbor-catalogue.json` 记录。

普通阵容总阳光不超过原包满级阳光容量5500，同种不超过10株，格子不重叠，阶数不超过各植物自身上限。同种植物保持一致阶数以匹配原生PlayerPlantData结构，不同种类混合阶数。奖杯越高，可用阳光预算、种植数量、单株费用范围和阶数范围总体提高；每次随机选取的阵容并非严格强弱排序。新种类由候选池抽取，而非仅使用豌豆、卷心菜和坚果。

## 更换、保存和战报

住宅面板原生按钮204接入本地免费更换。名字、奖杯、阵容和阶数随新对手更新，只影响选中的住宅。新区域首次生成和更换均先原子保存再投影到原生地图；失败保留旧对手，不跳入旧服务器请求。重复/跨玩家旧面板回调被拦截。已种植物不通过叠加方式覆盖，侦察/进攻仍沿用既有清场和同场转换。

每个玩家单独的 `.neighbors` 文件保存16处住宅的完整阵容、随机状态和序列号，大小11864字节，校验并通过临时文件、fsync、rename提交。文件损坏时拒绝加载，不静默重置。此文件位于userdata，受现有备份/回档脚本覆盖，不提交私有实例。

钱包升级为v14/788字节，在v13后追加最近10条战报的名字种子/特殊类型。各旧版本按原长度和校验迁移。战报固定记录交战时对手名字，更换邻居不改写旧战报；原有v13战报保留，不伪造旧名字数据。战报、军队损失和收益仍同次原子提交。
