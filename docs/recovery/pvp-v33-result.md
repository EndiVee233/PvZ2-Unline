# v33：本地防守布阵入口候选

用户复测 v32：WSA USER 首次进攻完成后（阶段 9）没有占领引导；点击自家基地“布置防守”短暂显示服务器通讯后消失，未进入布阵。该轮已回档，32 个文件校验通过。

原生地图按钮处理 `0x100b3d8` 的事件 206：阶段 1/2 走首次教程布阵，其他阶段在 `0x100b4c0` 调用 `0x1043028`，后者只是向旧服务器 `0xf87154` 发起请求。

候选修复仅把这一处调用改到原有本地加载函数 `0x85e7d8`。该函数设置 LawnApp `+0x1218 = 0`，加载现有 `arena_plant_test`，使用其原生关卡加载回调。首次教程分支、进攻分支和玩家教程阶段都未修改。其他模式的服务器请求不一并接管。

`arena_plant_test` 本身是原版普通 ArenaPlantProperties / PVPSeedBankProperties 布阵关卡，并非首次教程专用的 `arena_plant_tutorial`。不额外解锁植物或改造关卡配置。

当前目标是验证能进入、摆放和退出。尚未实现布阵保存本地化、重启恢复与后续占领玩法；不能将能进入视为完整防守功能恢复。

构建：`python scripts/build_pvp_v33.py`。以完整 v32 为基础，只有原生库四字节发生变化，其余 APK 负载逐项 CRC/大小一致；签名和对齐由构建脚本检查。

用户已验证可进入布阵；但蓝旗缺失，反复出现网络故障弹窗，无法充分测试摆放。该轮已关闭游戏并回档，32 个文件一致。入口已验证，摆放与退出未通过验收，v33 不作为完整功能修复发布。
