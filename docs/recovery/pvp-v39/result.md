# v39：恢复启动与可重复兑换码

用户报告 v38 启动闪退，并要求在原兑换码系统中添加可重复领取的 `admin`，每次获得 100 钻石与 10000 金币。

v38 的新增可写缓存段采用移动程序头表的布局，WSA 两次在 Houdini ELF 加载阶段发生相同的整数除零崩溃。v39 保持 `e_phoff=52`、`e_phnum=8` 和 PT_PHDR 不变；复用仅供直接执行 ELF 使用的 PT_INTERP 槽位，追加 VA `0x1b00000` 的 RW PT_LOAD。原有代码、数据、DYNAMIC、ARM_EXIDX、RELRO 段均保留，LOAD 按虚拟地址递增排列。此库由 Android dlopen 加载，不作为独立可执行程序。

在游戏原生 GetGemsRestoreUI 与新手礼包提交入口（`0x852a40`、`0x84adb8`）前检查 GNU UTF-32 输入字符串。精确匹配小写 `admin` 时，在游戏事件线程使用原有 Profile 钻石/金币奖励方法，刷新余额并沿原有持久化通知保存；不访问旧兑换服务器，不写入已使用兑换码标记。关闭成功提示后可以再次提交。接近原生整数货币上限时，两项奖励一起拒绝发放，避免只到账其中一种。其他输入回到原提交函数。

此前移除寻物启事时隐藏了原补偿码界面的商店入口。本版在钻石商店复用该界面的原生卡片和点击回调，显示“兑换码 / 输入兑换码领取奖励 / 兑换”。不生成原寻物启事装饰横幅，清空可选的旧寻物图片，保留正常卡片与按钮。输入对话框同步显示兑换码标题。

保留 v38 的三档星币价格（110/440/1650 钻石兑换 5000/20000/75000 星币）、本地训练队列、v37 邻居/布阵候选，以及已验收的 v36 修复。PVP 保存、侦察、进攻、邪恶戴夫完整引导、升级与研究仍未完成实际验收，不宣称完整离线 PVP 已完成。
