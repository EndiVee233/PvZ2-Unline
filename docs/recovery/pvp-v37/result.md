# v37 离线邻居候选版

在已验收的完整 v36 上追加原生本地后端；其他 APK 负载的大小和 CRC 保持，签名及对齐检查通过。游戏运行结果仍待用户测试。

实现范围：
- 使用原版 `PROPERTIES/RANDOMSTRINGS.TXT` 中的 30 个前缀与 60 个植物后缀生成六个稳定、互不重复的邻居名。名字原文仅从用户本地原资源提取，不把资产重新加入仓库。
- 六个邻居分布在第一区及第二区，采用豌豆射手、坚果、卷心菜投手的不同预设防守组合。
- 接入原生地图记录、查看阵容和普通进攻入口。空训练队列使用原生构造与验证插入，补充初始本地队伍；尚未验证实际进攻/结算。
- 自家布阵通过应用自己的 `files/userdata/offline-pvp-<profile>.def` 持久化；原子写入、格式/玩家/长度/坐标/校验和检查。查看邻居不会覆盖此文件。该路径包含在存档备份和回档范围内。
- 初期 PVP 教程阶段保持原流程；正常地图阶段补入邪恶戴夫事件的服务器结果字段，让原版引导获得触发机会，完成标记仍由原版对话回调记录。尚未验证触发及后续流程。

构建：`python scripts/build_pvp_v37.py`。需要本地 v36 APK、原始 pvz2data.zip、NDK 和既有签名证书。`--native-only` 只构建原生部分用于检查。

`python scripts/check_offline_pvp_arm.py` 在非零加载基址运行 APK 内实际编译的 ARM 后端，使用明确的引擎边界替身检查：邻居去重、教程阶段隔离、布阵含字符串的数据往返、损坏文件拒绝、写入失败不离开编辑器、查看邻居后恢复自家阵容。该检查不代替实际游戏测试。

构建同时拒绝扁平原生负载中未重定位的绝对指针，并检查嵌入段与编译器对齐一致。

当前边界：攻防完整闭环、战斗结算、离线占领/反攻以及邪恶戴夫全流程仍需逐项验证和补齐，不能视作已完成。私有游戏数据和日志只保存在忽略目录。

用户实测：侦察/出击提示没有僵尸可出战；训练场只有 1 星币，旧星币充值无效。日志中 `initial-army a=0`，证明旧 starter 没有通过原生 TrainingType 校验，不能把 ARM 引擎边界替身的检查当作实际出战验收。已读取日志并回档，32 个文件逐一校验通过。保存重进、邻居阵容、邪恶戴夫引导和实际战斗仍未验收。后续先恢复星币购买和正常训练。
