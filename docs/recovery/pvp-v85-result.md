# v85 基地布阵卡槽快捷键（候选）

v84 的点击悬停、十字提示、右键取消及保存/重启已验收，33 文件已回档。本轮接通用户此前报告无效的基地 PVP 卡槽按键，仍按玩家实际测试结果验收。

## 原因与修改

普通关卡桥接只查 `UISeedBank`，随后按普通 SeedPacket 类型和标志读取。基地布阵使用独立 PVPSeedBankModule，其 `+0x48` 是植物卡槽弱引用，`+0x40`、`+0x50` 分别对应技能与僵尸卡槽；卡片也是不同的 SeedPacket_PVP。继续套用普通类型会拒绝选取，且其可用性字段不能照抄普通卡片。

仅对 `arena_plant_test` 且 manager kind=1 的基地布阵，查当前 Board 的模块并解析真实植物卡槽；检查原生对象类型、可交互状态、当前页、每页槽数和实际数量，通过原生 SeedBank 取卡函数取得可见卡片。1～4、Q/W/E/R 对应当前页第 1～8 槽，不映射隐藏页。商铺 kind=2 继续没有卡槽和快捷选卡，不绑定技能或僵尸栏。

选卡仍使用原桥接的控件命中和 App 的普通按下/松开事件，禁用、阳光不足、卡片数量和教程/弹窗遮挡由原控件处理，不直接生成植物或改资源。选中后的预览恢复到最后悬停位置。普通关卡、右键、D/F/V/M/空格/A 与悬停收集的代码路径保留。

## 构建与程序检查

把同一桥接源码独立编译并链接进本轮原生 payload，仅重定向旧桥接入口 `0x1a010a4`，原 Java 按键/悬停队列不变。该入口在新增 LOAD 段，按虚拟地址与文件偏移的映射写入，避免误写其他区域；新增对象也检查无裸绝对 ARM 重定位。

扩展原桌面输入专项，执行候选 SO 中实际安装的入口跳转，在加载基址 0 和 0x20000000 下检查普通关卡旧行为、八键映射、当前页/尾页、槽位边界、弱引用/类型、商铺拒绝、暂停/遮挡、原 UI 取消动作及非零 Board 原点的预览恢复。原生 UI 对资源不足的真实表现、实际种植和第二商铺拖动隔离待用户验收，不把模拟的 UI 事件边界算作实机通过。
