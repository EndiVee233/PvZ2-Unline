## 费用显示根因

上版错误地把 `ARENA_PVP_BTN` 当成侦察页攻击按钮。实际翻译是“更换对手”，挂接 `0x109b838` 不会改变侦察页显示。旧测试直接给此错误入口提供自拟的“1攻击”文本，因而通过，未验证真实本地化键和调用者；它没有证明用户看到的按钮正确。

真实攻击按钮使用 `ARENA_PVP_OCCUPY_BTN`，本地化模板 `{CURRENCY_COST}攻击！`。构造时 `0x109f308` 调用 `0xd06a04` 写入默认值 500，实时更新在 `0x10a7ffc` 再调用该格式化函数，从属性 `+0x5c` 读取原值 1。但 ARM32 实机检查证实，只改这两次调用仍显示 1：侦察激活的 `0x108ff10`、`0x1090248` 会再调用 manager 费用 getter `0x10449b8`，将旧价交给带货币图标的 setter `0x109fc48`，覆盖前面的纯数字文字。最终候选同时挂接这两次 getter 调用，给原生货币 setter 传入当前实际费用，保留原生图标及排版。不再挂接“更换对手”。实际扣费逻辑保持原样。

新测试除直接执行格式化入口，还执行真实侦察刷新尾段 `0x10a7fd4`，读取原始本地化键及默认价格 1，经过格式化到按钮文字 setter `0x109fc30`，核对四档费用。并执行侦察激活的两个后续更新尾段，验证带货币图标的最终 setter 收到 10/20/50/100，不再重新收到旧值 1。测试桩要求本地化键必须是 `ARENA_PVP_OCCUPY_BTN`，错误按钮不能再以假文本通过。
