# v16r10 启动与兑换修复（2026-11-01）

最终包：work/launch-fix/PvZ2-v16r10-currency-exchange.apk。基于用户验证的 v15，使用原证书覆盖安装。原 v16 与 r2–r9 均不能作为完成版交付。

启动故障来自 classes8.dex 的 string_ids：直接替换哈希后字符串不再排序，Android 拒绝加载 BootActivity。现在修改后重新组装小型启动 DEX，并验证排序、类数量、SHA1 与 Adler32。

新商店文字改为 ASCII 本地化键，仅这些键由追加 ARM 代码构造 UTF-32 字符串。其余键继续走原查询；21 个键检查和 WSA 实际显示均通过。

比例为 1 钻石=1000 金币，所得扣除 10%：10/50/100 钻石到账 9000/45000/90000 金币；20000/100000/200000/300000 金币到账 18/90/180/270 钻石。寻物启事、累计充值标题与奖励区域、所有赠送文案已移除。原版充值横幅有独立绘制调用，现额外跳过该调用。

金币支付有多条原消费通知路径。诊断记录证明读取与扣款均返回，但尚未进入本地发放就发生 SIGABRT。最终跳过 0x9323e8、0x932e58 的旧消费通知链，保留本地发放与临时对象清理；另一套商品卡的 0x933844 完成调用改用原通用本地发放函数。此前只修改 0x9312b8 的方案已撤销。

WSA 完整 r10 APK 覆盖安装后实测：
- 冷启动进入主页、地图、商店成功。
- 145 钻石/27570 金币，支付 20000 金币后为 163 钻石/7570 金币，无崩溃。
- 点击 100000 金币档位，提示金币不足，余额不变。
- 163 钻石/7570 金币，支付 10 钻石后为 153 钻石/16570 金币。
- 两页中文显示正常，寻物卡、充值标题、进度奖励和赠送文案消失。

重启保存及恢复测试前余额的结果见 exchange-v16-device-validation.json。私有存档备份不提交 Git。抽奖 Hook 库与 v15 逐字节一致，教程补丁和旧追加代码保留；此次未重新打关，抽奖/教程仍以此前用户验收为证据。

复现：python scripts/build_exchange_v16.py，再 zipalign 并用保留的 recovered-debug.keystore 签名。依赖 apktool.jar、Java、py3rijndael、pyelftools、keystone 与外部 pyvz2 RTON 编解码器。

检查：84 个原 ARM 余额边界/算术案例、21 个本地化键、资源语义差分、DEX 排序与完整性、ZIP CRC、v1/v2/v3 签名、zipalign。仿真边界不覆盖完整 UI 事件或磁盘持久化，设备证据另列。大额档位未逐档进行设备交易；数据与金额算术已检查。旧引擎整数上限策略未修改。
