# v164：包名迁移后的 PVP 存档路径修复

反馈：僵尸进阶和药水研究无法升级；基地防线保存后重进被清空。

## 已定位原因

改包名从 `com.popcap.pvz2cthd.reconstruction` 到 `com.pvz2unline.aster` 时，构建脚本替换了路径字符串并以 NUL 补齐原空间。编译器却已经把原始前缀长度 73 和后缀偏移 81 编译为 ARM 指令常量。新前缀只有 59 字节；玩家 ID、`.eco` / `.def` 和 `.tmp` 仍写在旧偏移，C 文件接口先遇到补齐的 NUL。

实际结果：钱包、基地阵型、不同玩家、临时文件与正式文件都变成同一个 `files/userdata/offline-pvp-` 文件名。阵型可能覆盖钱包，钱包校验失败后僵尸进阶和技能研究无法提交。不是仅仅丢失 UI 状态。

## 修复与证据

- 对两个实际原生路径函数各修正五条长度/偏移指令；不移动引擎地址，不改变存档格式。
- 打包改名流程同时修正指令，避免今后再次只改字符串。
- 修复打包器严格验证函数地址、指令和 PC 相对路径引用；不认识的库拒绝修改。
- 用已发布 ARM32 APK 的真实 ARM 指令执行 64 个回归场景：两种加载基址、四种玩家 ID（含 0 和最大无符号值）、钱包/基地阵型/两处商铺驻防及临时/正式路径。原包 64/64 失败；修复后 64/64 通过，32 种目标文件互不冲突，补丁重复应用无额外修改。
- ARM64 仅将同一补丁同步到其嵌入的 ARM32 引擎，不运行 ARM64 验收。

## 存档与验收边界

修复不删除存档或故障文件。此前正常的 `offline-pvp-<玩家ID>.eco/.def` 按原格式读取。错误公共文件里已被另一种记录覆盖的内容无法凭空恢复；本补丁不猜测并重写这些资料。测试前按项目规则备份，测试后回档。

上述回归证明路径冲突得到修正，实际游戏里的升级、保存重进及冷启动仍需 ARM32 用户验收，未据此直接标为已通过。

## v164 实测阻挡（未通过）

用户进入僵尸进阶时闪退，尚未执行升阶、研究和阵型保存。本批 57 个存档文件已回档并逐文件校验。

日志中的首个原生故障发生在 ASTC 解码工作线程，Houdini 报告 `libRestart.so` 的 `IntegerSequenceCodec::GetCountsForRange`；随后旧 Hook 的退出处理又引发 SoundPool 清理崩溃。不能把后者当成进阶页的原始故障，也不能据路径回归通过就宣称整项修复通过。

v165 ARM32 为诊断候选：保留路径修复和原 754 项预取索引，仅增加解码任务定位及原始 ARM 信号上下文日志，继续追查最初故障。诊断开关默认关闭；ARM64 不运行本轮诊断。

### v165 入口诊断结果

用户已结束本轮入口测试。日志显示原来紧邻崩溃的 256×512、6×6 ASTC 图集及后续 2048×2048 / 4096×4096 图集均成功解码，没有新增 Aster 崩溃记录，进程仍存活；57 个存档文件已回档校验。诊断日志改变了时序，解码结果也会留在缓存，因此这不能证明原来的解码闪退已经根治。

继续用 v165 检验进阶/研究与阵型持久化；未经这轮实际操作不把它们标为通过。

### v165 合并操作结果及第二处故障

用户完成进阶、血包研究、基地保存及重启后，在再次打开技能研究时闪退。日志确认：僵尸进阶扣300星币、加速扣5钻石；血包研究扣2000星币、加速扣3钻石；基地阵型保存和重新加载均为1株。冷启动重新读回16164星币以及血包二级记录。因此原来的文件路径冲突修复已有实际读写证据，但整轮仍有崩溃阻挡。

本次原始故障由 v165 信号记录捕获：GL线程，PC相对引擎地址 `0x133f814`、LR `0x1342990`，`r1=0`，读取 `r1+0x1c`。调用链经过技能卡片绘制 `0x1082ae4 → 0x11699c4`。它把未解析到的可选 PopAnim 传给绘图函数；此前已绘制卡片静态图片。此处不是 ASTC 工作线程，故障前相关图集均为缓存命中，不能继续把这次闪退归为解码器故障。

57个文件及临时移开的单张纹理缓存已恢复并校验。
